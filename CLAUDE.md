# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```bash
uv sync                                   # set up environment (uv is the standard here); all features (embeddings, predict) are core dependencies, pytest/httpx are the `dev` group uv sync includes
uv run pytest                             # run all tests
uv run pytest tests/test_dataset.py -k name_of_test   # run a single test
uv run yolo-workbench /path/to/dataset.yaml --category detection|segmentation [--no-browser]
uv run yolo-workbench /path/to/dataset_dir --category classification   # <root>/<split>/<class>/ image folders
uv run yolo-workbench --projects /path/to/projects                        # projects mode: many datasets in one folder
uv run yolo-workbench-server run --config config.toml                     # the server profile (projects mode, systemd); `check` validates without starting
```

Server deployment: `docs/server.md` (install or upgrade with `deploy/install.sh`, switch back with `deploy/rollback.sh`, `deploy/yolo-workbench.service`, `deploy/config.example.toml`); the plan is `SERVER_IMPLEMENTATION_PLAN.md`.

The embeddings feature additionally requires a local MongoDB for FiftyOne (see README.md for the docker command and `~/.fiftyone/config.json`).

## Architecture

FastAPI app for annotating, validating and training on YOLO datasets: a local desktop tool, or (`yolo-workbench-server`) a service on an internal network. Python backend in `src/yolo_workbench/`, vanilla-JS frontend served from `src/yolo_workbench/static/` with native ES modules and no Node.js/build step. `app.js` orchestrates the UI; shared state and API helpers live in `state.js`/`api.js`, virtualized galleries in `grid.js` (only visible rows are in the DOM; `indicesInRect`/`enableMarquee` hit-test rectangle selection against the grid geometry, not the DOM), and the annotation editor, model-assisted labeling, and embedding renderer in `canvas.js`, `predictor.js`, and `embeddings.js` (the editor loads `/images/{id}/file?v=<image_version>` from the image detail — cacheable only under the current version — and prefetches the neighboring images); `sam.js` is the editor's smart annotation mode (click/right-click/box prompts → `/images/{id}/sam/segment`, with the Max points limit for polygons kept in `localStorage.samMaxPoints`; ⏎ pushes the result through `save()`; once the button was used — `localStorage.samUsed` — each opened image is encoded right away). `manage.js` is the Dataset tab (classes, import, splits, trash & backups); `repair.js` the raw label-file editor and the Validation tab's unknown-class panel; `labelqa.js` the Label QA tab (cards of findings with crops from `/qa/images/{id}/findings/{key}/crop`, apply/dismiss, Open passes `openEditor` a `{ annotation, box, hint }` focus: select, zoom, outline the model's shape — a polygon in segmentation); `projects.html`/`projects.js` is the projects list; `status.js` polls `/api/v1/status` for the server-wide warning banner (low disk space) on both pages; `user.js` is the signed-in user's header menu (change password, sign out) on both pages, and `login.html`/`login.js` the sign-in page (loads without a session, imports nothing; `next=` must be a local path). `collab.js` is several people in one project: it polls `/changes?since=<revision>` every 3 s (other people's changes: gallery refresh, `datasetChanged({ schema, keepEditor, keepSelection })`, the editor's "changed by … — Reload" notice), sends the editor's presence heartbeat (`/presence`), and renders who has an image open, who last edited/reviewed it, and the Dataset tab's activity list. `api()` sends `X-Workbench-Client` (`CLIENT_ID`, one per page load, so the feed leaves out the tab's own changes), redirects to the login page on 401, and attaches `status`/`body` to thrown errors; `toast()` moves the toast into an open modal dialog (the editor is drawn above everything else). `training.js` is the Training tab (runs list, live run view polling `/training/runs/{id}/epochs?since=`, header chip and read-only banner from `/api/v1/training/queue`; `?tab=training&run=<id>` deep-links a run) `trainform.js` its new-run form (a Training data panel of split folders — the run's `folders`, null = all, shown when a split has several; GUI fields and raw YAML editing one args object — a value equal to the framework's default is dropped; raw → GUI goes through `POST /training/args/validate`; the framework, Ultralytics or RF-DETR, follows `model:` (`rfdetr-…` variants) and picks the fields, defaults and model picker from `options.frameworks`; last-used args per dataset and framework in localStorage), `augments.js` the form's Augmentation group (a card per augmentation: slider plus previews of both range ends from `/training/augment/*`, fetched as blobs for the `X-Preview-Note` header; previews load only for open, on-screen cards; it also exports `loadImage`/`showZoom`), `rfaugments.js` RF-DETR's Augmentation group (`aug_config`: a preset — RF-DETR's default flip, none, or one of its four presets — then a card per Albumentations transform: chance, parameters from the server's catalog (`/training/augment/rfdetr/catalog`, introspected from the installed Albumentations), order, and two seeded random draws from `/training/augment/rfdetr`), `compare.js` its run comparison (per-run color slots kept while a run stays ticked, args diff against each run's framework defaults; also exports `bestEpochRow`/`shortModel` for `training.js`), and `charts.js` its dependency-free SVG line chart (series colors are the `--series-N` CSS variables, validated per theme). Dataset API calls go through `api()`/`apiUrl()` with paths relative to the dataset base (`/api/v1` in single mode, `/api/v1/projects/<slug>` in projects mode); paths starting with `/api/` are absolute.

Two modes: **single-dataset** (`create_app(dataset)`, dataset API at `/api/v1`) and **projects** (`create_workspace_app(workspace)`, workspace API at `/api/v1/projects`, `/api/v1/trash`, and the same dataset router mounted at `/api/v1/projects/{slug}`). Both share `dataset_router()` in `web.py` (endpoints get a `DatasetSession` through a dependency) and `/api/v1/app` (mode) plus `/api/v1/jobs`.

- `cli.py` — Typer entrypoint (desktop): loads a `Dataset`, takes the folder's owner lock, starts uvicorn on localhost, opens the browser.
- `server.py` — `yolo-workbench-server` (`run`, `check`): the server profile, projects mode only. `run` loads the configuration, `prepare_environment` points library caches at `cache_dir` and turns off Ultralytics' runtime pip installs (before torch/Ultralytics/FiftyOne are imported), takes the owner lock, and `build_app` applies `runtime.configure`, builds the `Workspace` and `create_workspace_app` with guards on and server `LifecycleOptions`. `check` reports folders (also against the installed unit's sandbox, `systemctl show`: it runs outside it), disk, lock, accounts, GPU, libraries and MongoDB without starting. `user add|passwd|remove|admin|list` manage the accounts (`load_config(..., serving=False)`: only the projects folder is needed).
- `auth.py` — sign-in (server profile, `[auth] enabled`; never in the desktop CLI). `UserStore`: `<projects>/.workbench/users.json` (scrypt hashes, `generation` bumped by a password change or removal, which ends that user's sessions); the CLI and the server both edit it under a file lock (`users.lock`) and the server re-reads it when its stat changes. `SessionStore`: `sessions.json` holds SHA-256 digests of random tokens with a sliding expiry (`session_days`, persisted at most hourly). `AuthMiddleware` (pure ASGI, inside the Host/header guard) lets through only valid sessions except `OPEN_PATHS` (login page and assets, `/healthz`, `/readyz`, `/api/v1/auth/login|logout|me`): `/api/` gets 401, pages a 303 to `/login.html?next=`; it sets the request's user and re-sends the cookie when the session slid. `require_admin` exists for future admin-only routes (none yet). Routes: `/api/v1/auth/login|logout|me|password`; `/api/v1/app` has `auth` and `user`.
- `identity.py` — who is acting, as context variables (standard library only): the user (`current_user`, `who()` = `{name, display_name}` stored with what they did), the browser tab (`X-Workbench-Client`, set by `RequestContextMiddleware`, always installed), and an action label (`with identity.action("delete images")`: the outermost label wins). Background work captures `snapshot()` and runs under `restored()` (JobManager does so for every job).
- `activity.py` — `ActivityLog`: `<dataset>/.yolo-workbench/activity.jsonl`, one line per change by a signed-in user (time, user, action, image ids capped at 200, count), rotated to `activity.1.jsonl` past 16 MB; `GET /activity` lists it.
- `config.py` — `ServerConfig`: every server setting with its default, grouped in TOML tables (field metadata names the table and key); CLI > `WORKBENCH_<FIELD>` environment > file > default; unknown keys are errors. `deploy/config.example.toml` must list every field (a test loads it).
- `runtime.py` — `RUNTIME`: process-wide limits and switches consulted deep inside (upload limits, `min_free_bytes` for `fsutil.ensure_free_space` → `InsufficientSpace` → HTTP 507, undo budget, path import, cwd model scan, GPU policy, retention days, embeddings switch). Desktop/test defaults; `runtime.configure(config)` applies the server's. Tests that change it must restore it.
- `ownership.py` — `OwnerLock`: one workbench process per folder (`<projects>/.workbench/owner.lock`, or `<dataset>/.yolo-workbench/owner.lock`), an OS lock (`flock`/`msvcrt.locking`) released with the process; `owner.json` says who holds it (and its release).
- `release.py` — which installed release the process runs: `install.sh` writes `release.json` (name, commit, install time) into `/opt/yolo-workbench/releases/<name>/`, beside the `.venv` (`sys.prefix`); read once (`release_info()`, cached; tests `cache_clear()` it), reported by `/readyz`, `/api/v1/app`, `check`, the startup log and `owner.json`. None outside an installed release.
- `lifecycle.py` — `Lifecycle` (on `app.state.lifecycle`, run by the FastAPI lifespan both factories install; `ASGITransport` in tests does not run it — use `app.router.lifespan_context(app)`): `startup()` starts the training supervisor and (server) the maintenance thread; `shutdown()` stops new work, `training.begin_shutdown(pause=…)` (server: the active run pauses at its next checkpoint), `jobs.close`, closes every open session (`DatasetSession.close`, `Workspace.close_all`), SAM, then `training.wait_for_pause`. Maintenance (server): idle model unload, `Workspace.close_idle`, `Dataset.rotate_session`, disk check, and every `interval` staging cleanup + `storage.apply_retention` for every project + expired project trash. Also `enforce_model_limit` (prediction models across open projects), `gpu_warning`/`refuse_gpu_load`. While stopping, mutating requests get 503.
- `logs.py` — logging setup: the server routes everything (uvicorn included, `log_config=None`) through one root handler, text or JSON; the desktop CLI only gives the `yolo_workbench` loggers a console handler.
- `dataset.py` — the core. `allow_empty=True` (projects) permits no images and no classes. Records can be added/removed at runtime (`_add_record`/`_remove_record`, `rescan()` diffs disk against the index). The undo stack holds transactions of mixed entries — `HistoryEntry` (label content), `FileEntry` (data.yaml), `MoveEntry` (classification class change), `RecordMoveEntry` (image + label to another split, to `.yolo-workbench/trash/`, or back), `FileMoveEntry` (a file of no record: orphan labels to the trash), `DirEntry`/`DirMoveEntry` (class folders), `SchemaEntry` — replayed by `_run_transaction`, which checks every entry before touching anything and re-reads records at the end. New multi-file operations should build entries and call `_execute`. A split may list several image folders (`train: [images/a, images/b]`); `_split_folders` holds them in YAML order (`.txt` lists and single files are sources but not folders), `folder_label()` is how the API names a folder (relative to the root), `resolve_folder(split, label)` picks one (default: the first), and `add_folder()` creates a folder (plus its `labels/` twin) and appends it to the split in the YAML as one undoable step (`SchemaEntry(layout_only=True)`: replay re-reads the layout, schema listeners are not called). `delete_images`/`move_images` (to any split folder) and imports require `capabilities()["image_ops"]` (at least one split folder). The undo stack is bounded (`_push_history`: `runtime.undo_max_transactions`/`undo_max_bytes`, oldest dropped); `rotate_session()` starts a new backup/trash session (the server does it daily), and `referenced_trash_sessions()` names the trash sessions undo/redo still point into (never purged). The history is per user (`Transaction`, a list of entries with `user`, `who`, `action`, `seq` and, for non-schema ones, the class `names` it was written for): `history()` takes the requesting user's latest transaction (without sign-in everyone is `None`: one plain stack), a new transaction drops only its author's redo, and replay checks every label entry's exact file content (`_check_entry`) and that the class list still matches, so undoing an older change never overwrites someone else's later one; `_history_conflict` names who changed the same paths or the class list since; a class change (`_check_schema_replay`) is refused while another user's later transaction is still applied or after an import/rescan, since its labels were written for the other class list. A move's replay is refused when a label appeared at the image since. Every change other browsers should see goes through `_record_change` (bumps `revision`, appends to a bounded change log with author and browser tab, writes the activity log and "last edited by" when someone is signed in); `changes(since)` reports others' changes (`reset`/`structure`/`schema`/`images`). Saves may carry the `schema_generation` they were made with: `check_schema` raises `SchemaChanged` (409 with `schema_generation` and the composed old→new class `mapping` from `_schema_log`) when the class list changed since. `close()` stops size probing. `Dataset` resolves the YOLO YAML (dirs, `.txt` file lists, colocated or parallel `images/`→`labels/` layouts), indexes every image with a stable sha1-based `record_id`, parses labels, and collects validation issues (malformed lines, unknown classes, out-of-range/zero-area/duplicate annotations, `overlap` (two objects at IoU ≥ `overlap.OVERLAP_IOU`, filled-polygon IoU in segmentation; reported on the later line, fixable — deleting it — only for the same class), missing/orphan labels — most marked `fixable` and repaired via `fix_issue`/`fix_issues_bulk`: a malformed line is removed (`_without_lines`, the issue carries its `line`), an orphan label moves to the trash (`trash_orphans`); `write_label_text` saves raw text (malformed lines allowed) through `_commit_many`, and `_prepare_text` is the unvalidated counterpart of `_prepare`). Public entry points that read records or indexes take `_lock` (an RLock), because the background probe thread updates them. All writes go through `_commit`: mtime-based conflict detection (`WriteConflict` → HTTP 409), one-time per-session backup under `<dataset>/.yolo-workbench/backups/<session-id>/`, atomic write (temp file + fsync + rename), and an undo/redo stack of transactions (each a list of before/after label-file contents, so bulk operations undo as one unit). Bulk operations (`fix_issues_bulk`, `bulk_edit_objects`) check all mtimes before writing any file — a conflict aborts the whole batch. Image dimensions are probed separately from label parsing (EXIF-upright, see `imaging.py`): cached in `<dataset>/.yolo-workbench/index.json` (`{version, images}` keyed by path with mtime_ns+size; bump `SIZE_INDEX_VERSION` when probing changes; saved every few seconds while probing) and re-probed via a thread pool — in a background thread when `background_probe=True` (the CLI default), with progress in `Dataset.indexing` / the `indexing` field of `GET /api/v1/dataset`.
- `web.py` — `create_app(dataset)` builds the FastAPI app: JSON endpoints under `/api/v1` (images, annotations PUT, object crops, issues, history, embeddings) plus Pillow-rendered thumbnails/crops. `DatasetError` → 400, `WriteConflict` → 409, `UploadTooLarge` → 413, `InsufficientSpace` → 507. `/healthz`, `/readyz` (skip the Host check), `/api/v1/status`, `/api/v1/app` (mode, `server`, `features`). Uploads (`/import/staging/{id}/files`, `/models/upload` into the dataset's `models/`) stream through `receive_file` into a dot-prefixed partial file and are committed whole.
- `media_cache.py` — disk cache for rendered thumbnails/crops under `~/.cache/yolo-workbench/media` (tests must pass a tmp dir via `create_app(dataset, media_cache=...)`). Keys hash image/label mtimes so edits self-invalidate; served with `Cache-Control: private, no-cache` + ETag (304 on revalidation); LRU-pruned by mtime past 512 MB. Bump `PALETTE_VERSION` when rendering or the palette changes.
- `imaging.py` — EXIF orientation: label coordinates refer to the upright image (as browsers, SAM, the importer crop, and Ultralytics see it), so every server render (`upright_rgb`) and size probe (`upright_size`) applies it. Project covers carry a `cover_version` in `project.json`.
- `review.py` — `ReviewStore`: per-image review status (`done`/`needs_work`, with `by` when signed in) and the last edit by a signed-in user (`edited_by`/`edited_at`, saved debounced by `Dataset._record_change`, flushed on close) in `.yolo-workbench/review.json` keyed by dataset-relative path; `ImageRecord.review`/`reviewed_by` mirror it (set in `_make_record`, so restored records get theirs back), `_relocate` moves keys, `Dataset.set_review` writes it. Not on the undo stack and allowed while training. `list_images`/`next_unreviewed` share `_filter_images` (`review=done|needs_work|unreviewed`, `issue=any|none|<kind>`, `reviewer=<name>`, `folder=<folder_label>`; `_folder_of` matches by path prefix, as `is_relative_to` takes seconds over 100k images); the web layer's `image_filters` dependency parses the same query for both.
- `storage.py` — per-session trash and backups under `.yolo-workbench/`: sizes, restore a session's trash to its dataset paths (then `rescan()`; taken names stay in the trash), and purge earlier sessions (never the current one, nor trash the undo history points into). `apply_retention(root, dataset)` deletes sessions older than the runtime's retention days, for open and closed datasets.
- `labelqa.py` — Label QA (`LabelQAManager`, `session.labelqa`): runs the predictor's loaded backend at `QA_CONF` over a split in a thread (`predictor.backend_lock` serializes inference; `predictor.external_busy` blocks model loads and batch runs meanwhile; backends get `predict(path, conf=)`), stores raw predictions per image in `.yolo-workbench/labelqa.json`, and derives findings (`missing_label`, `wrong_class`, `box_mismatch`, `unmatched_label`; one greedy pairing pass ranked by confidence × box IoU — same class from IoU 0.1, other classes from 0.5 — so a weak other-class guess cannot take a label from a confident right-class box; a same-class pair is a loose box only when an edge is off by more than the listing's `tolerance` px or 5% of the object's longer side) from the current labels on every listing, cached per image and tolerance by label revision. Lookups by key (apply, dismiss, crop) use tolerance 0, a superset of every listing. A finding's `key` hashes its kind and shapes (as the model drew them); listed, rendered and applied segmentation polygons go through `predictor.shape` (the predictor's `max_points`, shared with the editor; the Label QA tab edits it too); apply goes through `replace_annotations`, dismissals are stored per image. An image whose file changed since the analysis is stale. Lock order: dataset lock before the QA lock.
- `predictor.py` — optional model-assisted labeling. `PredictorManager` on `app.state.predictor`: loads a .pt/.onnx model (`UltralyticsBackend`) or RF-DETR weights (`RFDETRBackend`: `.pth`, or a `.pt` whose pickle names no Ultralytics class — `frameworks.weights_framework`; given the EXIF-upright image, per-class NMS at the predictor's IoU, masks → polygons via `masks.py`; switching framework without an explicit conf resets it to the backend's `default_conf`), auto-maps model class names to dataset classes case-insensitively (unmapped predictions are shown but not acceptable), lists models for the picker (`discover_models`: recents, the dataset's runs, weights under the dataset root, the working directory when `runtime.scan_cwd_for_models`, and recents' directories; `project_only` — every project session — keeps it to the project's folder and its recents, since the working directory may be the projects folder), unloads after `idle_unload` without use (`unload_if_idle` parks it: status `parked`, model path, options, class names, mapping and pending predictions kept, and `reload()` — called by `run`, `predict_image` and Label QA's `start`, through the web layer's `with_model` for the GPU policy and `max_loaded_models` — loads it again; `unload(run, reason)` for a training run or the model limit carries the message the UI shows and needs a load by hand), `model_upload_target` names an uploaded model's place in `models/`, simplifies segmentation polygons to at most `max_points` (`PUT /predictor/options`, saved in `.yolo-workbench/predictor.json`; `masks.simplify_polygon`, re-applied to pending predictions from their kept `raw_points`, which the API never returns), and runs batch inference in a background thread. Predictions live in memory keyed by image id until accepted — acceptance merges them via `replace_annotations` so backup/undo/conflict machinery applies; rejection never touches disk. Tests inject a fake backend via `PredictorManager(dataset, backend_factory=...)` and `create_app(dataset, predictor=...)`. CLI can preload a model with `--model`.
- `masks.py` — mask → annotation helpers shared by SAM and RF-DETR predictions (`drop_specks`, `mask_outlines`, `mask_box`), and `simplify_polygon` (a point limit: Douglas–Peucker at the smallest pixel tolerance that fits picks the vertices on the ~1 px resampled outline, then rounds of per-edge least-squares lines, vertices moved to their lines' intersection — bounded, projected instead when nearly parallel — and re-split stretches, kept while the squared distance to the outline drops).
- `sam.py` — smart annotation (SAM 2.1 via Ultralytics' `SAM2Predictor`). One app-wide `SamManager` (`app.state.sam`, routes `/api/v1/sam` + `/sam/start`; the per-image `encode`/`segment` endpoints are in `dataset_router`) so projects mode loads the model once; `unload_if_idle` frees it after the server's idle time (`idle_unloaded`: `sam.js` loads it again on the next use; an unload for a training run keeps it off until turned on again). `start()` loads in a background thread: `sam2.1_l.pt` when a GPU is available, falling back to `sam2.1_b.pt` (also when large fails). Images are encoded once, EXIF-upright, into a small LRU keyed by path+mtime; each prompt only runs the decoder. Masks first lose SAM's specks (`drop_specks`: islands under 4×4 low-res cells or 1% of the largest part), then become a box (around every remaining part; the editor draws all of them) or a polygon (largest contour, `approxPolyDP`). Read-only: nothing is written server-side. Tests inject `SamManager(backend_factory=..., gpu=...)` and `create_app(..., sam=...)`.
- `embeddings.py` — optional FiftyOne/UMAP 3D patch-embedding visualization, computed in a background thread with status polled via `/api/v1/embeddings`; degrades to `status: "unavailable"` when fiftyone isn't installed.
- `models.py` — `Annotation` and `ImageRecord` dataclasses.
- `session.py` — `DatasetSession`: a `Dataset` plus its `PredictorManager`, `EmbeddingsManager`, and `LabelQAManager`; `busy_reason()` blocks closing it while a job runs; `close()` stops its background work; `last_used` drives idle closing. `presence` (in memory): which browser tab of which signed-in user has which image open in the editor, forgotten `PRESENCE_TTL` (30 s) after its last heartbeat; `others_present()` leaves out the requester.
- `workspace.py` — projects mode. `Workspace(root)` lists, creates, updates, adopts, trashes (`<root>/.trash/`, `purge_expired_trash`), restores, and purges projects (`<slug>/project.json` + always a `data.yaml` without `path:`, so Ultralytics resolves paths next to it). Several projects are open at once: `sessions` is an LRU pool of up to `max_open`; `workspace.session(slug)` opens a project (closing the least recently used idle one when full, `WriteConflict` when all are busy), `close`/`close_idle`/`close_all`; `active` is the most recently used. Card summaries and the cover (first image → `.yolo-workbench/cover.jpg`) are persisted in `project.json` so listing never loads a `Dataset`.
- `classes.py` — class schema operations (add, rename, remove as delete or merge, merge, reorder), plus `resolve_unknown` for an id used in labels but missing from `names:` (map it to a class, add it as the next contiguous id, or delete its lines). Detection/segmentation compile to one transaction rewriting each label's class token (geometry text kept byte for byte) plus the YAML `names:` block (`yamledit.write_key` edits only that block, keeping comments); classification compiles to folder/file moves. Each transaction ends in a `SchemaEntry`, so replay reloads names and schema listeners (predictor mapping, embeddings) get the old→new id mapping.
- `importer.py` — import from a local folder (off on a server: `runtime.allow_path_import`) or a browser upload (`.yolo-workbench/staging/<id>/`, paths sanitized; streamed with per-file/per-upload limits, `clean_staging` removes dirs untouched for a day — each received file touches its dir): `scan()` pairs images with labels, detects source splits and class names (`data.yaml`, `classes.txt`, `notes.json`), suggests a mapping by name; `run_import()` adds new classes, assigns splits (fixed / seeded ratios / keep source), skips exact duplicates, copies files, then `Dataset.rescan()`. An optional crop (`crop_options`: center W×H or a region x/y/W/H, px or percent; `crop_box` is mirrored by `cropBox` in `manage.js`) works on the EXIF-upright image, re-encodes it, and clips labels (`crop_label_text`: boxes clipped, polygons Sutherland–Hodgman, objects under 10% visible dropped); duplicates are checked on the cropped bytes. `GET /import/sample` renders one of the scan's `samples` for the crop preview. Logged to `.yolo-workbench/imports.jsonl`; not on the undo stack.
- `jobs.py` — `JobManager` for background jobs with progress and cancel (imports). `JobManager(synchronous=True)` runs inline for tests. `close(timeout)` (shutdown) cancels and joins running jobs and refuses new ones. A job records `started_by` and its work runs as whoever started it (`identity.restored`, action = the job kind).
- `frameworks.py` — what differs between Ultralytics and RF-DETR runs (plan: `PLAN-rfdetr.md`): a `Framework` per trainer (`ULTRALYTICS`, `RFDETR`) for argument schema/defaults/validation, pretrained models, a run's weights (`weights(run_dir)`), resume checkpoint, fitness and results files. `frameworks.validate()` picks the framework from `model:` (`rfdetr-…` → RF-DETR). A run's framework is `run.json`/`spec.json` `framework` (absent = Ultralytics); external RF-DETR runs are recognized by `training_config.json` + `metrics.csv`. RF-DETR arguments are checked against a static copy of rfdetr 1.11's `TrainConfig` (`_RF_FIELDS`; importing rfdetr takes seconds and loads torch, so the server never does — `test_schema_matches_the_installed_rfdetr` keeps it in sync; bump with the `<1.12` pin). RF-DETR's logged metrics are normalized to the workbench's epoch-row keys (`metrics/mAP50-95(B)`, `train/ce_loss`, `lr/pg0`, …) by `normalize_rfdetr_metrics`. Also holds the shared JSON/YAML helpers and the Ultralytics argument code (`validate_args`, `ultralytics_defaults`, re-exported by `training.py`).
- `training.py` — training runs, Ultralytics or RF-DETR (plans: `PLAN-training.md`, `PLAN-rfdetr.md`). `TrainingManager` (on `app.state.training`; in projects mode `workspace.training`, one queue for all projects) lists runs under the dataset's runs root (`<project>/runs/`, or `<dataset dir>/runs/` in single mode; external `yolo train` runs too), keeps a persistent FIFO queue (`queue.json`) with one active run, and `tick()` reaps the active process and launches the next. Constructing it launches nothing (it only restores the dataset lock); `start()` (the lifespan) does the first tick. The queue can be `held` (persisted; `set_hold`, "Hold & pause" pauses the active run too); runs paused for a service stop or a hold are listed in `auto_resume` and go back to the front once launching is allowed; `begin_shutdown`/`wait_for_pause` implement the server's stop. The active entry is saved before `Popen`, and a run without `process.json` is found again by its spec path (`_find_runner`) instead of being launched twice. A run is launched as a detached subprocess (`train_runner.py`, own session, survives server restarts; reattached via `process.json` PID + create_time) on a generated `workbench/data.yaml` with absolute per-split file lists (Ultralytics), or a `workbench/splits.json` snapshot of images + parsed labels (RF-DETR; its runner builds the folder RF-DETR needs). Both come from `_data_plan`, rebuilt at every launch (resumes too); a run limited to some split folders keeps them in `spec.json` `folders` (`{split: [folder_label]}`, absent = everything; not for classification), and `run.json`'s `dataset` records them. Weights paths, resumability and results come from the run's `frameworks.Framework`. While a run is active its dataset is read-only: `attach(dataset)` sets `Dataset.write_guard`, and `check_writable()` (called by `_commit_many`, `_run_transaction`, and imports) raises `DatasetLocked` (a `WriteConflict` → 409). The guard is read lock-free (`_locked` snapshot) because writers hold the dataset lock. Args are YAML validated against Ultralytics' `cfg/default.yaml` and `check_cfg`. Right before a run launches, `before_launch(run, project)` (set by `web._unload_before_training`) frees the GPU — with `LifecycleOptions.unload_for_training` "all" (desktop; the server with `gpu_models_during_training = refuse`): `SamManager.unload` and every open dataset's `DatasetSession.unload_models`; with "project" (the server's default): only the trained project's session. `unload_models` stops Label QA's analysis (and `PredictorManager.unload` cancels a batch run; pending predictions, mapping and model path stay), then `free_gpu_memory()` (also `malloc_trim`s the heap on Linux, so model load/unload cycles do not grow the server's memory); their payloads' `unloaded` says why, and the editor does not reload SAM by itself until smart annotation is turned on again. Tests inject `launcher=` (fake process handles) and write the runner's files themselves; the real smoke test runs with `WORKBENCH_SLOW_TESTS=1`.
- `augment_preview.py` — augmentation previews for the new-run form. Detection/segmentation execute Ultralytics' own transforms (`ultralytics.data.augment`) on dataset images with labels: range ends pin every random draw in that module to the low/high end (`augment.random`/`augment.np` swapped under `_render_lock`), pipeline samples swap in seeded generators of their own (`_seeded`: other threads draw from the global ones, pymongo for every FiftyOne write) and seed torch's global one for torchvision, restoring it. Classification uses the torchvision ops `classify_augmentations` composes. Renders at `min(imgsz, 640)` with `perspective` rescaled.
- `rfdetr_runner.py` — the RF-DETR side of the subprocess (`train_runner` dispatches on `spec.json` framework). RF-DETR reads only split folders inside one root and ignores EXIF, so it builds `<run>/workbench/data/` from the server's `splits.json` snapshot (images hardlinked → symlinked → copied under numbered names, EXIF-rotated ones re-encoded upright, labels written from the parsed annotations; removed at exit, rebuilt on resume). Trains through `RFDETR.train()` with `WorkbenchCallback` appended to every Lightning trainer it builds (`rfdetr.training.build_trainer` is wrapped in the process). Pause/finish set `trainer.should_stop` at an epoch end (Lightning still saves `last.ckpt`); kill only sets a flag (`Reporter(raise_on_kill=False)`) and the callback raises at the next batch boundary. Periodic full checkpoints are off unless `checkpoint_interval` is set. After a finished fit, evaluates the best weights on val (per-class AP) and test into `val.json`/`test.json`. RF-DETR's output_dir is the run folder: `checkpoint_best_total.pth` (best, written at fit end; `_ema`/`_regular` meanwhile), `last.ckpt`, `metrics.csv`, `training_config.json`.
- `rfdetr_augment.py` — RF-DETR's `aug_config` (Albumentations transforms RF-DETR applies after its resize). `catalog()` lists the transforms and their parameters (signature defaults, `Literal` choices) with their kind: `geometric` (in `GEOMETRIC`, a copy of RF-DETR's `GEOMETRIC_TRANSFORMS`: boxes/masks follow), `pixel`, or `unmoved` (moves the image, RF-DETR leaves the labels). `check()` builds every transform as RF-DETR does (`_build`, containers included) because RF-DETR skips one that fails with only a log line; it reports unknown transforms and parameters, and transforms the Kornia (GPU) backend cannot run (`KORNIA`, a copy of its registry). `PRESETS`/`GEOMETRIC`/`KORNIA` are kept in sync with the installed rfdetr by a test. `render()` previews on a dataset image square-resized to `min(resolution, 640)`, each transform wrapped like RF-DETR does (geometric ones with bbox params, seeded per step). No aug_config = RF-DETR's torchvision default (a horizontal flip), `{}` = none.
- `export_runner.py` — ONNX export of a run's best weights, a subprocess per export (`TrainingManager.export_onnx` runs it as an `export` job on `jobs`; cancel kills it; tests inject `exporter=`). Exports a copy of the weights on the CPU in `workbench/export-tmp/` and moves the `.onnx` next to the best weights (`best.onnx`, `checkpoint_best_total.onnx`) only when complete; RF-DETR exports at the trained resolution restored from the checkpoint unless the dialog asks for another (`shape=`; a multiple of the variant's step, checked by `_rfdetr_export_size`). `workbench/export.json` records the options and the weights' mtime, so the run summary's `onnx` reads as stale once the best weights change. Only `import` jobs hold back a queued run or a project switch.
- `train_runner.py` — the subprocess: Ultralytics callbacks write `workbench/state.json` (≤1/s) and `epochs.jsonl`, final `val.json`/`test.json` (test-split eval of best.pt); `control.json` from the server asks to pause (raise after the epoch's checkpoint, resumable), finish early (`trainer.stop`), or kill. Kill is SIGTERM on POSIX; Windows has no catchable cross-process signal, so a watcher thread turns control.json's `kill` into `_thread.interrupt_main(SIGTERM)` — both land in `Reporter.on_sigterm`, which defers it past checkpoint writes. Force-kill after `KILL_GRACE` is `killpg` on POSIX, a psutil process-tree kill on Windows (`terminate_process`/`kill_process_tree` in `training.py`). `on_fit_epoch_end` also fires from `final_eval()` — that call is not an epoch. Deletes the `labels/*.cache` files it created. `Dataset` never indexes or orphan-scans `<dataset dir>/runs/`.

The category (`detection` = 4 points cx/cy/w/h, `segmentation` = polygon, ≥6 even-count points, `classification` = no points) is fixed at launch and branches validation, rendering, and geometry throughout backend and frontend. All coordinates are normalized 0..1. Classification datasets are directories (`<root>/<split>/<class name>/images`, class ids = sorted class-dir names); there are no label files — the class edit is a file move committed via `_commit_moves` (`MoveEntry` history entries, same undo/redo stack, no backups since moves are non-destructive), and the predictor reports `unavailable`. Embeddings work for classification too: `compute_gt_viz` embeds whole images (`fo.Classification`, no `patches_field`) instead of object patches.

Windows is supported: use `fsutil.replace` instead of `os.replace` (Windows refuses to replace a file another process has open, so it retries briefly), write label/YAML/list files with `newline="\n"`, and keep paths shown to the API or written to YAML POSIX-style (`as_posix()`). `pyproject.toml` takes torch/torchvision from the PyTorch CUDA index on Windows only (PyPI's Windows wheels are CPU-only).

The class-color `PALETTE` is duplicated in `web.py` and `static/api.js` — keep them in sync.

The CLI and the server enable two request guards (off by default in `create_app`/`create_workspace_app`, so tests need not send them): a Host allow-list (DNS rebinding; the server's comes from `allowed_hosts` and stays on with a wildcard bind) and a required `X-Workbench: 1` header on mutating `/api/` requests (cross-site forms/uploads). `api()` in `api.js` always sends the header. The server adds sign-in on top (`auth.py`); the desktop app has none.

## Tests

Tests build isolated temporary datasets (`make_dataset` in `tests/test_dataset.py`) and must never modify a real dataset. API tests use httpx `ASGITransport` against `create_app` — no live server.
